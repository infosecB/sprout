# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Sprout": Water, feed and repot every houseplant on time, with a care log for each one. A SwiftUI iOS 17+ app (iPhone and iPad) with a widget extension and a one-time "Sprout Pro" in-app purchase. No third-party dependencies; Swift 5 mode. Made from [app-factory](https://github.com/infosecB/app-factory).

## Build and run

The Xcode project is generated by XcodeGen from `project.yml`. The generated `Sprout.xcodeproj` **is checked in** (Xcode Cloud reads the project and shared scheme from the repo), so commit it after every regenerate. Never hand-edit it:

```sh
xcodegen generate          # after adding/removing files or editing project.yml
open Sprout.xcodeproj
xcodebuild test -project Sprout.xcodeproj -scheme Sprout \
  -destination 'platform=iOS Simulator,name=iPhone 18 Pro' CODE_SIGNING_ALLOWED=NO
```

- Targets: the app (`Sprout/` + `Shared/`), the widget extension `SproutWidgets` (`SproutWidgets/` + `Shared/`) and `SproutTests` (Swift Testing). All `.swift` files in those folders are picked up automatically; a new file needs a regenerate, not a project edit.
- Code both targets need goes in `Shared/`, so it must not touch app-only types (`Store`, `AppSettings`, views in `Sprout/`) or extension-unavailable API.
- `APP_BUNDLE_IDENTIFIER` in `project.yml` is the one place the bundle ID lives; the widget ID (`.widgets`) and the App Group (`group.<bundle id>`) are derived from it. The App Group name reaches code through the `AppGroupIdentifier` Info.plist key (`SharedDefaults`).
- Info.plist keys with no `INFOPLIST_KEY_` setting (URL scheme, App Group name, the widget's `NSExtension`) and the entitlements live in `Config/`. Everything else is in `project.yml`; changes made in Xcode's UI are lost on regenerate.
- The scheme uses `Sprout.storekit`, so Pro (`com.brendanchamberlain.sprout.pro`) can be bought locally without App Store Connect. A test checks the file sells `Store.proID`.
- `Sprout/PrivacyInfo.xcprivacy` and `SproutWidgets/PrivacyInfo.xcprivacy` declare UserDefaults use. Update both, `PRIVACY.md` and `docs/privacy/index.html` if you add a required-reason API, a network call or any data collection.
- `docs/` is the public GitHub Pages site at https://infosecb.github.io/sprout (`docs/CNAME` sets the domain): home, privacy policy and support. The app links to the last two (`AppWeb` in `About.swift`); App Review requires that.
- Releases: run the GitHub Actions **Release** workflow; it tags `main` (bare `MAJOR.MINOR.PATCH`) and Xcode Cloud archives the tag, with `ci_scripts/ci_post_clone.sh` stamping the tag into `MARKETING_VERSION`. Don't bump versions by hand. See `RELEASING.md`.

## Architecture

- `SproutApp` owns the `@Observable` models and puts them in the environment: `Store` (StoreKit 2 Pro unlock, caches `isPro` so features don't flicker off at launch) and `AppSettings` (persisted choices, `didSet` → `UserDefaults`).
- `RootView` holds the `TabView` (tabs are `AppTab` in `Shared/AppLink.swift`), presents `PaywallView`, applies the appearance, handles `sprout://` links and parked navigation from intents, and writes the `WidgetSnapshot`.
- **Pro gating is done at the point of use, not by deleting state.** Read `store.isPro`, fall back to the free behaviour, and make locked controls open the paywall instead of acting. `ProFeatures.swift` lists what Pro unlocks; keep it in step with the README, `Sprout.storekit`'s description and `APPSTORE.md`.
- **Widgets never read the app's state.** The app resolves what they show into `WidgetSnapshot` (in `Shared/`), saves it to the App Group and reloads timelines only when it changed (`RootView.updateWidgets()`; call it whenever displayed data changes). Widgets open the app with `AppLink` URLs; the iOS 18 control runs `OpenAppIntent`, which parks a tab in `PendingNavigation`.
- **Look:** all colours and display type go through `Brand` (`Shared/Brand.swift`); `Brand.accent` matches the `AccentColor` asset, `--accent` in `docs/assets/style.css` and `accent` in `appstore/frame-screenshots.swift`. Change all four together.
- **Layout:** read the size from a `GeometryReader`; `Brand.isWide(size)` (squarish/landscape, e.g. the iPhone Duo cover screen) switches to side-by-side layouts and `Brand.margin(for:)` gives the edge margin. Scrolling screens use `.scrollBounceBehavior(.basedOnSize)`.
- **Screenshot mode:** in Debug, `-demoPro YES` unlocks Pro and `-demoTab <tab>` picks the tab; any `UserDefaults` key can be set with a launch argument. `appstore/take-screenshots.sh` relies on this; add `-demo…` flags (read in `#if DEBUG`) for sample data.
- Respect `accessibilityReduceMotion` for anything that animates continuously.

## Claude tooling

- **Hooks** (`.claude/settings.json`): after any edit or shell command, `.claude/hooks/sync-project.sh` regenerates the Xcode project if `.swift` files were added, removed or renamed or `project.yml` changed, so you don't need to run `xcodegen generate` yourself (still commit the regenerated project). At session start, `.claude/hooks/session-start.sh` says whether this machine can build at all.
- **Permissions**: building, testing, simulator control, the `scripts/` and `appstore/` scripts and read-only git/gh are pre-approved. Pushing, running workflows and creating releases always ask.
- **Skills** (`.claude/skills/`): `run-app` (build, launch and look in the simulator), `screenshots`, `consistency-check` (`scripts/check-consistency.py`), `release-preflight` (checks, version, then the Release workflow only on the user's yes) and `add-feature` (recipes: Pro feature, widget data, App Intent, screen, SwiftData).
- **App Store Connect** (`app-store-connect` MCP server from app-factory, registered per user; see `~/gh/app-factory/mcp/appstoreconnect/README.md`): `app_status`, `list_builds`, `xcode_cloud_runs`, `get_listing` and `list_reviews` read freely; `create_app_version`, `update_listing` and `set_testflight_notes` ask first. The bundle ID to pass is `APP_BUNDLE_IDENTIFIER` in `project.yml`. Submitting, releasing and replying to reviews are left to the user in App Store Connect. If the tools are missing or return a setup error, point the user at that README rather than working around it.
- Run `scripts/check-consistency.py` after touching Pro features, privacy-relevant code, the listing or the accent colour.

## Conventions

- Keep `README.md`'s feature list and file map up to date when adding features or files.
- Mark Pro features "(Pro)" in the README and listing: App Review rejects descriptions that present paid features as free (guideline 2.3.2).
